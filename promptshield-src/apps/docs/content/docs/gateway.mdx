---
title: Gateway
description: PromptShield's inline gateway role in the combined product.
---

In the combined PromptShield + Bifrost product, Nginx is the only public entry
point. Public `/v1/*` traffic goes through PromptShield first for policy,
rate limits, token budgets, audit logging, and metrics, then continues to
Bifrost for provider routing.

```text
Client -> Nginx /v1 -> PromptShield Gateway -> Bifrost /v1 -> LLM provider
```

Bifrost owns provider credentials, key pools, fallback order, model routing, and
router governance. PromptShield remains inline before provider routing and does
not expose a separate public inference endpoint.

## Product setup

Run the full product stack from the repository root:

```bash
cp .env.example .env
docker compose up -d --build
```

The PromptShield Gateway service listens only on the Compose network. Public
clients use the product gateway:

```python
client = OpenAI(base_url="http://localhost/v1", api_key="local")
```

## Modes

**Security mode** scans requests with the detection engine before they reach
Bifrost.

```bash
PROMPTSHIELD_ENGINE_URL=http://promptshield-engine:4321
PROMPTSHIELD_ENGINE_API_KEY=<engine-shared-secret>
```

**Gateway mode** keeps PromptShield inline for gateway controls without
detection-engine scanning.

```bash
PROMPTSHIELD_ENGINE_URL=none
```

## Provider keys and routing

Configure provider credentials, key pools, fallback order, and model routing in
Bifrost through `http://localhost/bifrost/` from an allowed admin network. Keep
PromptShield configured as an OpenAI-compatible upstream to Bifrost:

```bash
PROMPTSHIELD_PROVIDER=openai-compatible
PROMPTSHIELD_OPENAI_COMPATIBLE_UPSTREAM_URL=http://bifrost:8081/v1
```

## Policy hot reload

The gateway watches the policy file and reloads changes atomically. If a reload
fails, the previous policy stays active.

```bash
PROMPTSHIELD_POLICY_PATH=/policy/policy.yaml
```

Dashboard policy controls and the authenticated internal admin API update
PromptShield policy and security settings only. Provider/routing changes belong
in Bifrost.

## Streaming

SSE streaming is supported. Token usage is extracted from stream chunks and
counted against budgets. Response scanning is skipped on streaming responses.

```python
with client.chat.completions.stream(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Tell me a story"}],
) as stream:
    for chunk in stream:
        print(chunk.choices[0].delta.content or "", end="", flush=True)
```
