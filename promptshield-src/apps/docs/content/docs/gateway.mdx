The gateway is a single Go binary. In the combined PromptShield + Bifrost product
it handles inline policy enforcement, rate limiting, token budgets, audit
logging, and Prometheus metrics before traffic reaches Bifrost. Bifrost owns
provider routing and provider API keys.

## Requirements

- Go 1.22+ (build from source) or download a pre-built release

## Install

**From source:**

```bash
git clone https://github.com/promptshieldhq/promptshield-gateway
cd promptshield-gateway
```

**Download a release:**

Grab the binary for your platform from [releases](https://github.com/promptshieldhq/promptshield-gateway/releases).

## Configure

```bash
cp .env.example .env
```

Combined-product minimum:

```bash
PROMPTSHIELD_PROVIDER=openai-compatible
PROMPTSHIELD_OPENAI_COMPATIBLE_UPSTREAM_URL=http://bifrost:8081/v1
```

Configure provider API keys and model routing in Bifrost, not in PromptShield.
See [Environment Variables](/docs/environment-variables) for the full list.

## Run

**From source:**

```bash
make run
# listening on :8080
```

**From release binary:**

```bash
./promptshield-gateway
# listening on :8080
```

## Verify

```bash
curl -s http://localhost:8080/health
# {"status":"ok","service":"promptshield-gateway"}
```

## Connect your app

Change `base_url` in your SDK. No other code changes needed.

```python
client = OpenAI(base_url="http://localhost:8080/v1", api_key="sk-...")
```

## Modes

**Gateway mode** (default) — no engine needed. Rate limiting, token budgets, API key rotation, audit logging, and Prometheus metrics work out of the box.

```bash
PROMPTSHIELD_ENGINE_URL=none
```

**Security mode** — full PII and secrets scanning on every request.

```bash
PROMPTSHIELD_ENGINE_URL=http://localhost:4321
PROMPTSHIELD_ENGINE_API_KEY=your-engine-key
```

See [Engine](/docs/engine) for setup.

## Provider keys and routing

Provider credentials, key pools, fallback order, and model routing are managed in
Bifrost. Keep PromptShield configured as an OpenAI-compatible upstream to
Bifrost so blocked requests stop before provider routing.

## Policy hot-reload

The gateway watches the policy file for changes and reloads atomically — no restart required, no requests dropped. If a reload fails, the previous policy stays active.

```bash
PROMPTSHIELD_POLICY_PATH=config/policy.yaml  # default
```

You can also update policy at runtime via the [Admin API](#admin-api) without touching the file.

## Streaming

Full SSE streaming is supported. Token usage is extracted from stream chunks and counted against budgets. Response scanning is skipped on streaming responses.

```python
with client.chat.completions.stream(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Tell me a story"}],
) as stream:
    for chunk in stream:
        print(chunk.choices[0].delta.content or "", end="", flush=True)
```

## Admin API

Four authenticated endpoints for runtime configuration without restarts.

**Requires:**

```bash
GATEWAY_ADMIN_TOKEN=your-secret-token
```

### Get current config

```bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  http://localhost:8080/admin/config
```

### Update configuration

```bash
curl -X PUT -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "security",
    "engineUrl": "http://localhost:4321",
    "providerMode": "single",
    "provider": "openai"
  }' \
  http://localhost:8080/admin/config
```

Changes persist to disk.

### Get policy

```bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  http://localhost:8080/admin/policy
```

### Update policy

```bash
curl -X PUT -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/yaml" \
  --data-binary @config/policy.yaml \
  http://localhost:8080/admin/policy
```

Policy reloads immediately in-memory. No restart needed.
