---
title: SDK Integration
description: Point your existing OpenAI SDK at the production gateway. One line change.
---

The combined gateway accepts the same request format as OpenAI's `/v1/chat/completions`.
Point your SDK's `base_url` at the public Nginx `/v1` endpoint so traffic
passes through PromptShield before Bifrost. Nothing else changes.

## Python

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost/v1",
    api_key="local",
)

response = client.chat.completions.create(
    model="gemini-2.0-flash",
    messages=[{"role": "user", "content": "Hello"}],
)
print(response.choices[0].message.content)
```

Streaming works the same way:

```python
with client.chat.completions.stream(
    model="gemini-2.0-flash",
    messages=[{"role": "user", "content": "Tell me a story"}],
) as stream:
    for chunk in stream:
        print(chunk.choices[0].delta.content or "", end="", flush=True)
```

## The model field

The `model` field in the request body is passed through to Bifrost. Model
selection, provider fallback, and provider routing are configured in Bifrost.

## Provider API keys

Provider API keys belong to Bifrost in the combined product. Do not send
provider keys to PromptShield or store them in PromptShield environment files.

```python
client = OpenAI(
    base_url="http://localhost/v1",
    api_key="local",
)
```
