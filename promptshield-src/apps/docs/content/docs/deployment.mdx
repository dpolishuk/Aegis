---
title: Production Deployment
description: Deploy the combined PromptShield + Bifrost gateway product.
---

The production deployment is the combined gateway product from the repository
root. Nginx is the only public listener; PromptShield, Bifrost, the detection
engine, and dashboard services stay on the internal Compose network.

## Configure

```bash
cp .env.example .env
```

Set production values for:

```bash
POSTGRES_PASSWORD=<database-password>
BETTER_AUTH_SECRET=<32-plus-character-secret>
PROMPTSHIELD_ENGINE_API_KEY=<engine-shared-secret>
AUDIT_INGEST_SECRET=<audit-shared-secret>
CONFIG_ADMIN_EMAILS=<real-admin-email>
```

Do not leave `CONFIG_ADMIN_EMAILS` unset if operators need policy or gateway
security configuration changes from the dashboard. There is no default admin
email.

## Start

```bash
docker compose up -d --build
```

Verify the public product gateway:

```bash
curl -s http://localhost/health
```

Public inference uses `http://localhost/v1`. Configure provider credentials,
model routes, key pools, fallback, and router governance in Bifrost at
`http://localhost/bifrost/` from an allowed admin origin.

## Verify Before Changes

```bash
scripts/verify-production-topology.sh
```

The verifier checks public `/v1` routing through PromptShield, blocks direct
Bifrost inference bypasses, confirms component services are internal-only, runs
focused dashboard/API type checks, and proves a PromptShield policy-blocked
request produces no Bifrost upstream hit.
